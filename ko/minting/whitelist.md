# 서명·Allowlist 민트

Allowlist 페이즈는 프로젝트가 지갑별 proof나 서명(voucher)을 요구할 수 있는 민팅 단계입니다. Nogada는 지갑이 “적격/부적격”이라고 추측해 선택이나 발사를 막지 않습니다. 필요한 실행 데이터와 실제 온체인 결과만 사용합니다.

## 앱에서 만드는 순서

1. **Smart Mint**에 컨트랙트, 블록 탐색기, OpenSea, 마켓플레이스, 런치패드 또는 프로젝트 민트 링크를 넣습니다.
2. 프로젝트가 실제 등록한 페이즈 이름 중 원하는 서명·Allowlist 페이즈를 선택합니다.
3. 지갑, 지갑당 수량, 가스, 예약 시각과 필요한 설정을 확인하고 **작업 만들기**를 누릅니다.
4. **작업** 화면에서 만든 작업을 선택하고 **Start**를 누릅니다.

Smart Mint가 작업을 만들 뿐, 그 자리에서 자동 발사하지 않습니다. 모든 앱 민팅은 작업의 Start에서 실행됩니다.

## OpenSea 서명 데이터

SeaDrop 서명 페이즈는 각 지갑의 voucher가 필요합니다. 앱은 작업 준비 단계에서 지갑별 데이터를 가져오며 다음 경로를 지원합니다.

* **OpenSea API**: 앱 **설정 → 연동**에 등록한 앱 전용 OpenSea API 키를 사용합니다.
* **기본 경로**: 사용자가 앱에 설정한 네트워크/프록시 경로로 가져옵니다.

앱과 Telegram 봇의 OpenSea 키·지갑·작업·RPC·프록시는 서로 공유되지 않습니다. 봇으로 민팅할 때는 봇 설정에 별도로 등록해야 합니다.

## 선택과 결과

* 별도의 WL 체크 결과나 적격 배지를 보여주지 않으며, 추측한 적격 여부로 지갑 선택 또는 Start를 막지 않습니다.
* proof·voucher처럼 실제 calldata 생성에 필요한 값이 오지 않으면 해당 지갑의 준비/실행 실패로 사실대로 표시합니다.
* 거래가 제출되면 hash를 보존하고 같은 거래의 영수증을 확인합니다. 미확정 거래에 새 nonce를 자동으로 만들지 않습니다.
* **민팅 완료**는 성공 영수증에서 기대한 NFT 컨트랙트·서명 지갑·수량을 확인했을 때만 표시합니다.
* 영수증 status는 성공이지만 정확한 NFT Transfer를 확인하지 못하면 **민팅 미검증**으로 구분합니다.

## 커스텀 컨트랙트

프로젝트 자체 컨트랙트가 지갑별 proof/서명을 요구한다면 Smart Mint가 해석한 경로를 먼저 사용하세요. 자동 해석할 수 없을 때는 프로젝트가 제공한 정확한 ABI/함수 인자 또는 calldata를 고급 작업에 넣어야 합니다. 앱은 임의 calldata의 의미를 추측해 수량이나 발사를 바꾸지 않습니다.
