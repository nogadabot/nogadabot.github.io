# 서명·Allowlist 민팅
GTD·FCFS·Allowlist 페이즈는 지갑별 proof 또는 서명(voucher)을 요구할 수 있습니다. 지갑 선택과 실제 실행 데이터 확보는 서로 다른 단계입니다.

## 준비 순서
Smart Mint에서 정확한 체인과 페이즈를 선택하고 지갑·수량·가스·예약을 저장합니다. 예약 작업은 Start를 미리 눌러 준비합니다.

**일반 사용자가 voucher를 미리 구해 직접 입력하는 흐름이 아닙니다.** 지원되는 OpenSea 서명 경로에서는 봇·앱이 지갑별 데이터를 자동으로 가져오고, 민팅 시각에 데이터가 공개되면 해당 데이터를 이용해 실행합니다. 프로젝트 API를 이용할 수 없거나 데이터가 오지 않으면 원인을 표시합니다.

OpenSea 키가 있는 경로와 기본 익명 경로의 조건은 다를 수 있습니다. 앱의 키·프록시는 앱에, 봇의 키·프록시는 봇에 따로 등록하세요.

페이즈의 가격·지갑당 상한·기간·서명 대상은 정확히 유지해야 합니다. 다른 페이즈나 다른 지갑의 서명으로 대체하지 않습니다. 프로젝트 자체 컨트랙트가 지원되지 않으면 공식 함수·proof·서명 규칙을 확인한 뒤 고급 작업을 사용해야 합니다.

별도 checker가 없다는 이유로 지갑을 부적격이라고 판단하지 않습니다. 반대로 필요한 proof나 서명을 확보하지 못했는데 전송 가능한 calldata가 있는 것처럼 표시하지도 않습니다.

성공은 [실제 영수증의 NFT 결과](../app-guide/results.md)로 확인합니다.
