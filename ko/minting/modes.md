# 민트 방식: 즉시 · 안전 · 연사

민트 방식은 작업의 거래를 언제, 몇 번 보낼지 정합니다. 어느 방식을 골라도 먼저 작업을 만들고 **작업 화면의 Start**에서 실행합니다.

## 세 가지 방식

| 방식 | 동작 | 적합한 경우 |
|---|---|---|
| **즉시 1회** | 선택한 지갑마다 시뮬레이션 없이 바로 한 번 실행 | 가장 낮은 첫 전송 지연이 중요할 때 |
| **안전 1회** | 사용자가 선택한 경우 같은 호출을 eth_call로 시험한 뒤 한 번 실행 | 실제 revert가 예상되는 거래의 가스를 아끼고 싶을 때 |
| **연사** | Stop, 사용자가 정한 상한, 또는 정확한 NFT 민팅 영수증 확인까지 반복 | 오픈 시각이 불확실하거나 여러 번 시도하려 할 때 |

안전 1회는 적격/WL 판정 기능이 아닙니다. 같은 순간·같은 호출에 대한 실제 시뮬레이션이며, 이 방식을 사용자가 선택하지 않으면 시뮬레이션 결과로 발사를 막지 않습니다.

## 예약 Start

시작 시각을 지정하고 Start를 미리 누르면 작업이 무장됩니다.

* 예약 전에는 지갑 키, RPC 연결, 가스, nonce, 승인과 결정 가능한 calldata를 준비합니다.
* 지정 시각에는 새 동기 RPC 조회나 원격 확인을 추가하지 않고 첫 raw 거래를 전파합니다.
* 지갑별 서명·voucher처럼 늦게 오는 동적 데이터는 도착 즉시 서명·전송합니다.
* Start 요청은 먼저 저장되므로 준비가 잠시 걸려도 다시 누를 필요가 없습니다. Stop으로 취소할 수 있습니다.

## 연사 설정

| 값 | 의미 |
|---|---|
| **지연(ms)** | 다음 시도까지 간격 |
| **최대 tx** | 한 지갑이 보낼 최대 전송 횟수. 성공 개수가 아님 |
| **종료/가드레일** | 사용자가 정한 자동 중지 시각 또는 실행 시간 |

연사는 단순히 영수증 status 1에서 멈추지 않습니다. 기대한 NFT 컨트랙트·서명 지갑·수량이 영수증에서 확인될 때만 민팅 완료로 자동 정지합니다. 거래가 미확정이거나 민팅 미검증이면 새 nonce를 자동으로 계속 만들지 않고 그 결과를 구분해 표시합니다.

## 수량과 여러 지갑

* 수량은 **지갑 한 개당 요청 수량**입니다.
* 총 목표 수량은 선택 지갑 수 × 지갑당 수량입니다.
* 알려진 1회 상한을 넘으면 정확한 요청량을 여러 nonce로 나눕니다. 수량을 몰래 줄이지 않습니다.
* 여러 지갑은 병렬로 준비·전송됩니다.
* 같은 지갑을 앱의 여러 작업에서 쓰면 앱 내부 nonce 조정기가 관리합니다.
* 독립 Telegram 봇과 앱은 nonce 상태를 공유하지 않습니다. 같은 지갑을 동시에 실행하는 것은 허용되지만 충돌할 수 있으므로 경고를 확인하세요.

## 가스와 Boost

각 nonce는 사용자가 설정한 가스로 한 번 발사합니다. 자동 RBF나 자동 fee escalation은 하지 않습니다. 실행 중 거래 가스를 바꾸려면 사용자가 **Boost**를 눌러야 합니다. 높은 tip은 포함 우선순위를 높일 수 있지만 채굴 순서를 보장하지 않습니다.

## 결과 기준

* **민팅 완료**: 성공 영수증에서 정확한 NFT Transfer를 확인.
* **실패**: 온체인 revert 또는 발사 실패가 확인.
* **확정 대기**: hash는 있지만 영수증이 아직 없음. 같은 raw/거래를 계속 확인.
* **민팅 미검증**: 영수증 status는 성공이지만 기대한 NFT 결과를 확인하지 못함.
* **일부 완료**: 지갑 또는 분할 거래 결과가 섞여 있음.
