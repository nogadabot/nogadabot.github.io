# 텔레그램 봇 사용법

Nogada 텔레그램 봇은 앱과 연결하지 않고 서버에서 독립적으로 실행되는 24시간 민팅 제품입니다. 봇에서 등록한 지갑·작업·RPC·프록시·OpenSea 키만 사용하며, 앱의 지갑이나 작업을 보거나 제어하지 않습니다.

> 앱과 봇은 제품 규칙과 검증된 민팅 코드를 공유하지만 실행 상태와 데이터는 공유하지 않습니다. 같은 지갑 주소를 양쪽에 넣는 것도 허용됩니다. 다만 두 제품이 같은 지갑으로 동시에 거래를 보내면 nonce가 충돌할 수 있으며, 이 선택은 사용자가 관리해야 합니다.

## 1. 앱 없이 로그인

1. Telegram에서 **@NOGADA\_Mint\_Bot**을 엽니다.
2. `/redeem 구매이메일`을 보냅니다.
3. 구매 이메일로 받은 8자리 코드를 10분 안에 `/redeem 12345678` 형식으로 보냅니다.

앱 설치나 앱 페어링 코드는 필요하지 않습니다. 새 Telegram 계정에서 로그인하면 이전 채팅은 로그아웃되지만 봇 지갑과 봇 작업은 보존됩니다.

## 2. 봇 지갑과 봇 전용 설정

**💼 지갑**에서 봇 지갑을 생성하거나 개인키를 가져오고, 민팅에 필요한 소액만 입금하세요. 봇 지갑 키는 24시간 서명을 위해 서버에 암호화되어 보관됩니다. 큰 자산은 별도의 안전한 자기보관 지갑에 두고, 민팅 후 **💸 회수** 또는 `sweep=`으로 옮기는 것을 권장합니다.

**🛠 설정**의 RPC·프록시·OpenSea API 키는 봇 전용입니다. 앱에 등록한 값은 봇으로 복사되거나 동기화되지 않습니다.

## 3. 가장 쉬운 민팅: 스마트 민트

1. **🔮 스마트 민트**를 누르거나 `/mint`를 보냅니다.
2. 봇 지갑이 1개면 자동으로 선택됩니다. 여러 개면 실행할 지갑만 고릅니다.
3. 지원되는 민트 링크나 컨트랙트 주소 하나만 보냅니다. 예:

   ```text
   https://opensea.io/collection/example
   ```

4. 화면의 체인 버튼에서 실제 배포 체인을 직접 선택합니다. 봇이 입력만 보고 체인을 자동 확정하지 않습니다.
5. 프로젝트가 등록한 페이즈가 여러 개면 실제 이름 그대로 표시됩니다. 원하는 페이즈를 선택합니다.
6. 민팅 설정 화면에서 지갑당 수량·발사 방식·예약·가스를 버튼으로 확인하거나 바꾼 뒤 작업을 만듭니다. 미래 페이즈는 게시된 시작·종료 시각을 기본값으로 제안합니다.
7. **⚙️ 작업 → 🤖 봇 작업**에서 내용을 다시 확인하고, 미리 **Start**를 눌러 무장합니다.

Smart Mint는 컨트랙트, 블록 탐색기, OpenSea 컬렉션·아이템·assets 링크, 마켓플레이스, 런치패드, 프로젝트 민트 사이트를 조회합니다. 보호된 페이지나 정보가 없는 임의 사이트처럼 자동 해석할 수 없는 입력은 컨트랙트 또는 ABI/Hex 수동 작업으로 이어가면 됩니다.

* 기본 수량은 **선택한 지갑마다 1개**입니다. 총 목표 수량은 `지갑 수 × 지갑당 수량`으로 표시됩니다.
* 수량·발사 방식·예약·가스는 명령어를 외울 필요 없이 매번 민팅 설정 버튼에서 정합니다.
* 알려진 1회 민팅 상한이 있으면 정확한 요청 수량을 여러 nonce로 나누어 실행합니다. 수량을 몰래 줄이지 않습니다.
* 페이즈 번호나 시간이 불완전하면 Public 또는 종료됨으로 추측하지 않습니다.
* 적격/WL 여부를 추측해 지갑 선택이나 Start를 막지 않습니다. 서명·proof처럼 실제 실행 데이터가 필요한 단계에서 얻지 못한 값은 해당 지갑의 준비/실행 결과로 사실대로 보고합니다.

## 4. Start와 발사 속도

모든 봇 민팅은 봇 작업을 만든 뒤 **봇 작업의 Start**에서 시작합니다. Smart Mint 조회 완료만으로 거래가 발사되지는 않습니다.

* 즉시 작업은 Start 요청을 저장하고 지갑·RPC·가스·nonce·민팅 데이터를 준비하는 즉시 발사합니다.
* 예약 작업은 미리 Start를 눌러 무장합니다. 가능한 정적 정보는 미리 준비하고 지정 시각에 첫 거래를 전파합니다.
* 같은 raw 거래를 여러 RPC에 전파할 수 있지만, 자동 RBF나 자동 가스 인상은 하지 않습니다.
* 같은 지갑을 앱에서도 동시에 실행할 수 있습니다. 봇은 이를 막지 않고 nonce 충돌 가능성만 알립니다.

## 5. 민팅 설정과 수동 입력

일반적인 Smart Mint에는 명령어 옵션이 필요하지 않습니다. 체인과 페이즈를 고른 뒤 나타나는 민팅 설정 화면에서 다음 항목을 버튼으로 정합니다.

* 수량: 지갑당 1·2·3·5개 또는 직접 입력
* 발사: 연사·1회·안전
* 예약: UTC 시작과 선택적 종료 시각 또는 프로젝트 게시 일정
* 가스: 자동 또는 최대 수수료·tip·gas limit 직접 입력

기존 한 줄 형식은 숙련 사용자용 선택지로 계속 지원합니다. 예:

```text
/mint https://opensea.io/collection/example sepolia 1 at=1787802000 until=1787802300 fire=spam gas=400000 max=3 delay=250 tip=2 fee=7
```

일반 Smart Mint 사용자는 이 형식을 직접 쓸 필요가 없습니다.

자동 조회가 부족하거나 직접 calldata를 지정하려면 **⚙️ 작업 → 🤖 봇 작업 → ➕**를 사용합니다.

```text
0x컨트랙트 [체인] [지갑당 수량] [한 번에 보낼 네이티브 토큰] [모드] + 옵션
```

주요 옵션:

| 옵션 | 의미 |
|---|---|
| `sig=mintPublic(uint256,address)` | 직접 지정할 함수 시그니처 |
| `args=2;{address}` | 함수 인자. `{address}`는 각 봇 지갑 주소로 치환 |
| `0x...` 모드 | 사용자가 만든 calldata를 그대로 전송 |
| `fire=spam` | 사용자가 Stop하거나 정확한 민팅 영수증이 확인될 때까지 연사 |
| `fire=safe` | 사용자가 선택한 시뮬레이션 포함 1회 경로 |
| `tip=5 fee=80 gas=120000` | 사용자 가스 설정(gwei/가스 한도) |
| `max=200 delay=500` | 연사 최대 전송 횟수와 간격(ms) |
| `at=+5m` / `at=16:59` | 예약 시작(UTC) |
| `until=17:00` | 연사 종료 시각(UTC) |
| `nft=0x...` | 라우터가 별도 NFT 컨트랙트를 민팅할 때 영수증 검증 대상 |
| `sweep=0x...` | 확인된 NFT를 안전 지갑으로 이동 |

민팅 NFT는 항상 거래에 서명한 봇 지갑이 받습니다. 별도 민팅 수령인은 지원하지 않으며, 민팅 뒤 옮기려면 `sweep=`을 사용합니다.

ABI/Hex 작업의 `수량`은 calldata를 다시 쓰는 값이 아니라 영수증에서 기대할 NFT 개수입니다. `nft=`도 라우터가 별도 컬렉션을 민팅할 때 결과를 확인하는 값일 뿐 호출 대상이나 calldata를 바꾸지 않습니다. SeaDrop처럼 의미가 확정된 경로에서만 전송 전에 증명 가능한 충돌을 알리며, 임의 calldata의 의미를 봇이 추측해 발사를 막지 않습니다.

## 6. 결과를 읽는 법

일반 흐름에서 봇은 다음 3개의 짧은 카드만 보여줍니다.

* **페이즈 카드:** 프로젝트, 체인, 확인된 경우의 현재 상태, 각 실제 페이즈의 가격·지갑당 상한·게시 시각
* **작업 카드:** 작업 번호, 페이즈, 선택 지갑과 수량, 발사 방식, 예약. 같은 지갑 nonce 경고는 여기서 한 번만 표시하고 Start·예약 알림·결과에서 반복하지 않습니다.
* **최종 결과 카드:** 민팅 확인·실패·확인 중·미검증 수, 짧은 지갑/거래 정보, 탐색기 링크, 지갑·회수 버튼

내부 플랫폼 이름, 민터 주소, selector, 준비 진단은 일반 카드에서 빼고, 사용자가 조치해야 할 실제 오류만 표시합니다.

| 상태 | 의미 |
|---|---|
| 제출/확정 대기 | 거래 hash가 있으며 아직 영수증이 확정되지 않음 |
| 민팅 완료 | 성공 영수증에서 정확한 NFT Transfer 컨트랙트·서명 지갑·수량을 확인함 |
| 실패 | 온체인 revert 또는 발사 실패가 확인됨 |
| 민팅 미검증 | 영수증 status는 성공이지만 기대한 NFT 컨트랙트·서명 지갑·수량을 확인하지 못함 |

확정 대기 중에는 새 nonce를 만들지 않고 같은 거래를 계속 확인합니다. 민팅 미검증 작업도 자동 재실행하지 않습니다. 사용자가 작업 상세에서 다시 Start할 수는 있지만, 새 거래가 나가 중복 민팅될 수 있다는 경고가 먼저 표시됩니다.

## 7. 꼭 기억할 것

* 봇과 앱의 지갑·작업·설정은 서로 보이지 않고 동기화되지 않습니다.
* Start 전에는 선택 지갑, 지갑당 수량, 총 수량, 총 전송 금액, 체인, 페이즈를 확인하세요.
* 높은 tip은 포함 우선순위를 높일 수 있지만 채굴 순서를 보장하지 않습니다.
* 드롭 감시의 공급량 변화는 민팅 오픈의 증거가 아닙니다. 알림은 신호일 뿐이며 실제 페이즈와 거래 결과는 온체인·공식 데이터로 확인합니다.
* 개인키, 이메일 인증 코드, 내보낸 키를 채팅 전달·화면 녹화·스트리밍에 노출하지 마세요.
