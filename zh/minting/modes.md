# 铸造方式：立即、安全与连发

铸造方式决定任务何时以及发送多少次交易。无论选择哪种方式，都必须先创建任务，再从**任务界面的 Start**执行。

## 三种方式

| 方式 | 行为 | 适合场景 |
|---|---|---|
| **立即** | 不模拟，对每个已选钱包执行一次 | 最重视首次广播延迟 |
| **安全** | 仅在用户明确选择时，对同一调用执行 eth_call，再执行一次 | 希望避免实际模拟 revert 的 Gas |
| **连发** | 直到 Stop、用户上限或准确 NFT 铸造收据确认前重复 | 开放时间不确定或需要多次尝试 |

安全模式不是资格/WL 分类器，而是对当时同一调用的实际模拟。用户未选择安全模式时，不会用模拟结果阻止发射。

## 预约 Start

设置开始时间并提前点击 Start，即可让任务进入准备状态。

* 钱包密钥、RPC 连接、Gas、nonce、授权和可确定的 calldata 会提前准备。
* 到达指定时刻后，不增加新的同步 RPC 或远程检查，直接传播第一笔 raw 交易。
* 钱包专属签名、voucher 等动态数据到达后会立即签名并发送。
* Start 会先保存，短暂准备期间无需再次点击；Stop 可取消。

## 连发设置

| 设置 | 含义 |
|---|---|
| **延迟（ms）** | 下一次尝试前的间隔 |
| **最大 tx** | 每钱包最大发送次数，不是成功数量 |
| **结束/防护时间** | 用户设置的自动停止时刻或持续时间 |

连发不会仅因收据 status 为 1 就停止。只有收据证明预期 NFT 合约、签名钱包和数量时，才以“铸造完成”自动停止。待确认或未验证结果不会自动持续创建新 nonce，并会单独显示。

## 数量与多钱包

* 数量是**每个钱包的请求量**。
* 总目标数量为“已选钱包数 × 每钱包数量”。
* 若存在已知单笔上限，会按多个 nonce 拆分准确请求，绝不会暗中减少。
* 多个钱包会并行准备并发送。
* 应用 nonce 协调器管理应用任务中的同钱包使用。
* 独立 Telegram 机器人与应用不共享 nonce 状态。同钱包并发使用是允许的，但可能冲突，请阅读警告。

## Gas 与 Boost

每个 nonce 使用用户设置的 Gas 发射一次。不会自动 RBF 或自动提高费用。执行中若需替换 Gas，请由用户点击 **Boost**。更高的 tip 可能提高优先级，但不保证打包顺序。

## 结果依据

* **铸造完成**：成功收据证明准确 NFT Transfer。
* **失败**：已确认链上 revert 或发射失败。
* **待确认**：已有 hash 但无最终收据，继续核对同一 raw/交易。
* **铸造未验证**：收据 status 成功但无法证明预期 NFT 结果。
* **部分完成**：钱包或分片结果混合。
