# 签名与 Allowlist 铸造

Allowlist 阶段可能要求每个钱包独有的 proof 或签名（voucher）。Nogada 不会猜测钱包“有资格/无资格”并据此阻止选择或发射，只使用实际需要的执行数据和链上结果。

## 在应用中创建

1. 在 **智能铸造**中粘贴合约、区块浏览器、OpenSea、市场、Launchpad 或项目铸造链接。
2. 按项目登记的准确名称选择签名/Allowlist 阶段。
3. 确认钱包、每钱包数量、Gas、预约时间及必要设置，然后点击**创建任务**。
4. 进入**任务**，选择已创建的任务并点击 **Start**。

智能铸造只创建任务，不会在查询页面直接广播。应用中的所有铸造都从任务中的 Start 开始。

## OpenSea 签名数据

SeaDrop 签名阶段需要每个钱包的 voucher。应用会在任务准备阶段获取该数据，并支持：

* **OpenSea API**：使用在应用 **设置 → 集成**中登记的应用专用 OpenSea API 密钥。
* **默认路径**：使用用户在应用中配置的网络/代理路径。

应用与 Telegram 机器人不会共享 OpenSea 密钥、钱包、任务、RPC 或代理。使用机器人铸造时，必须在机器人设置中单独登记。

## 选择与结果

* 不显示 WL 检查结果或资格标记，也不会用猜测的资格阻止钱包选择或 Start。
* 若无法取得构建 calldata 实际需要的 proof、voucher 等值，会如实显示该钱包的准备/执行失败。
* 交易提交后会保留 hash 并核对同一笔交易的收据；待确认交易不会自动创建新 nonce。
* 只有成功收据证明预期 NFT 合约、签名钱包和数量时，才显示**铸造完成**。
* 若收据 status 成功但无法证明准确 NFT Transfer，则显示**铸造未验证**。

## 自定义合约

对于需要钱包专属 proof/签名的自定义合约，请优先使用智能铸造解析出的路径。若无法解析，需要在高级任务中填入项目提供的准确 ABI/函数参数或 calldata。Nogada 不会猜测任意 calldata 的含义，也不会暗中更改数量或发射行为。
