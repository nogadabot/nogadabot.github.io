# 任务：所有应用铸造的起点

任务保存“铸造什么、使用哪些钱包，以及数量、Gas 和时间”。仪表盘仍是第一个界面，但**应用中的每笔铸造交易都必须先创建任务，再从任务界面的 Start 发射**。

## 最简单的创建方式

1. 在 **智能铸造**中粘贴合约、区块浏览器、OpenSea collection/item/assets、市场、Launchpad 或项目铸造链接。
2. 若项目登记了多个阶段，请按准确名称选择。
3. 确认钱包、每钱包数量、Gas、开始时间和必要选项。
4. 点击**创建任务**。
5. 进入**任务**，选择刚创建的任务并点击 **Start**。

在智能铸造与任务之间切换是预期流程。智能铸造查询完成或使用**快速任务**只会创建任务，不会自动广播。

## 任务界面

* **分组栏**：按项目或策略整理任务。
* **+ 新建任务**：打开手动/高级任务编辑器。
* **快速任务**：使用设置中保存的钱包与 RPC 创建任务，仍需从 Start 发射。
* **分组开始/停止**：对组内适用任务批量请求 Start/Stop。
* **批量编辑**：修改所选任务的共同设置。
* **每行 Start/Stop/Boost/日志/编辑/复制/删除**：直接控制单个任务。

准备状态仅用于说明。余额、预测失败或猜测的资格不会阻止 Start 或选择。Start 请求会先被保存，必要准备完成后自动发射。

## 手动合约、ABI 与 Hex 任务

自动查询不足时使用 **+ 新建任务**。

| 字段 | 含义 |
|---|---|
| 链 | 实际发送交易的链 |
| 交易目标 | 被调用的合约，可能是路由器/共享 minter |
| ABI 函数与参数 | 从 ABI 选择，或输入准确函数签名与参数 |
| Raw calldata | 原样发送用户提供的 hex |
| 每钱包请求数量 | 每个钱包收据中预期的 NFT 总数量 |
| 交易发送金额 | **单笔交易发送的原生代币总额**，不是每件价格 |
| 预期 NFT 合约 | 路由器从其他 NFT 合约铸造时的收据验证目标 |
| NFT 接收者 | 必须收到铸造结果的地址 |

ABI/Hex 的预期数量不会暗中改写 calldata 或发送金额。只有 SeaDrop 等协议语义明确且可证明数量冲突时才会在发送前提示；Nogada 不会猜测任意 calldata 的含义来阻止发射。

## 钱包与准确数量

* 界面会区分**每钱包数量**、已选钱包数与**总目标数量**。
* 若存在已知单笔上限，会按多个 nonce 拆分准确请求，绝不会暗中减少数量。
* 应用内的多个任务由应用 nonce 协调器管理。
* 同一钱包也可同时用于独立 Telegram 机器人，应用不会阻止。但两个产品不共享 nonce 状态，因此会提示冲突风险。

## 执行方式

| 方式 | 行为 |
|---|---|
| 立即 | 不模拟，立即发送用户选择的交易 |
| 安全 | 仅在用户选择时，对同一调用执行 eth_call，并对没有实际模拟 revert 的钱包发送一次 |
| 连发 | 直到 Stop、用户上限或准确 NFT 铸造收据确认前重复 |

安全模式是用户可选的交易模拟，不是资格分类器。若最重视首次广播延迟，请使用立即或预约执行。

## 预约与发射

提前点击 Start 可使预约任务进入准备状态。钱包密钥、RPC 连接、Gas、nonce、授权和可确定的 calldata 会提前准备。到达指定时刻后，不增加新的在线检查，直接传播第一笔 raw 交易。不会自动 RBF 或自动提高 Gas；执行中的 Gas 替换只由用户点击 **Boost** 触发。

## 结果状态

| 状态 | 含义 |
|---|---|
| 准备/排队 | Start 已保存，正在准备或等待预约时刻 |
| 已提交/待确认 | 已有交易 hash，正在核对同一笔交易的收据 |
| 铸造完成 | 成功收据证明了预期 NFT 合约、接收者和准确数量 |
| 失败 | 已确认链上 revert 或发射失败 |
| 铸造未验证 | 收据 status 成功，但无法证明准确 NFT Transfer |
| 部分完成 | 钱包或分片中同时存在完成、失败、待确认或未验证结果 |

待确认交易不会自动创建新 nonce。未验证任务也会从自动、分组与批量重跑中排除。用户可以在该行明确再次点击 Start，但应用会先警告每个执行钱包都可能发送新交易并导致重复铸造。

## 发射前检查

请确认所选钱包、每钱包数量、总目标数量、每笔交易金额、最大总金额、链、交易目标、NFT 接收者和阶段。链、目标、接收者、金额、已选阶段或协议语义明确的 calldata 数量发生变化时，属于用户意图不一致，不会发射。猜测的资格、余额、价格或应用/机器人使用同一钱包都不是阻止理由。
