# 结果与交易耗时

交易哈希、RPC 接收和 NFT 铸造成功是不同的事件。

## 查看任务行

**状态**保持简短，**结果**显示失败原因、交易链接和已有的链上证据。打开任务详情，可以查看原因说明和建议检查的项目。

| 结果 | 已知情况 |
|---|---|
| 铸造成功 | 已通过交易回执验证预期的 NFT 铸造结果 |
| 失败 | 已确认提交失败，或交易在链上执行失败（revert） |
| 待确认 | 已有交易，但最终回执尚未确认 |
| 未验证 | 已观察到交易，但尚未验证预期的 NFT 铸造结果 |
| 部分完成 | 不同钱包或分批交易的结果不同 |

不要仅因为刷新失败就重新启动任务。新一轮执行可能再次铸造。

## 结果汇总

在当前任务组中点击**结果汇总**，集中查看各钱包的结果和交易链接。NFT 总数只统计经过回执验证的铸造数量。

**下次更新：**结果按**任务 × 钱包**统计，并单独显示去重后的钱包数。同一钱包执行两个任务，算两条任务钱包结果、一个钱包。缺少结果的项目会显示为尚无报告；同一铸造回执不会重复增加 NFT 总数。

## 广播记录

任务详情中的首次提交和 RPC 接收耗时使用 **ms（毫秒）**，链上回执耗时使用 **s（秒）**。142 ms 等于 0.142 秒，7.811 s 等于 7.811 秒。未记录的数据会留空或标注为未记录，不会显示为零延迟。

提交被接收，不代表已上链或铸造成功。耗时来自实际记录，不能保证区块链的处理速度。

另见[故障排查](../help/troubleshooting.md)和 [Boost](../minting/boost.md)。
