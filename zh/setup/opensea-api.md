# OpenSea API 密钥

OpenSea API 密钥让应用可以使用 OpenSea 需要认证的功能。它和 RPC 不同：RPC 连接区块链，这个密钥连接 OpenSea。

## 需要密钥的事

- 创建和取消挂单
- 获取并接受报价
- 查看器批量购买
- 铸造日历日程
- 任务的 OpenSea API 模式

不需要密钥的事也有很多。市场和仪表盘的行情来自 Nogada 服务器，所以不需要密钥。Drop 铸造在普通模式和匿名模式下也不需要密钥。匿名模式只会对匿名请求没有得到回应的钱包，把密钥作为备用。

## 填入密钥

1. 在 **OS API** 菜单里创建或选择一个分组。
2. 点击 **添加密钥**，每行粘贴一个。空行和以 `#` 开头的行会被忽略。
3. 点击 **验证并添加**。

应用会在保存之前，逐个向 OpenSea 验证每个密钥。无效的密钥和重复的密钥不会被加入。

密钥平时是隐藏的。只有点击 **全部显示** 或复制时才会显示。

## 获取密钥

- **在 OpenSea 开发者设置里自己申请**：在 OpenSea 账户的开发者设置里提交申请，然后按上面的步骤填入。需要邮箱验证和一些简单的使用信息。
- **通过模块**：如果运营者在 **任务 → 模块** 里上传了 OpenSea 密钥模块，就能用那个模块生成。生成的密钥会加密保存在 OS API 里。

## 测试密钥

点击测试或 **全部测试**，会显示延迟。也请一并查看 **类型** 和 **到期** 两栏。确认没有会在 Drop 之前到期的密钥。

| 状态 | 处理方法 |
| --- | --- |
| 无效 | 删除后填入新密钥。用 **清除无效项** 一次删除 |
| 错误 | 检查连接后重新测试 |
| 即将到期 | 到期前填入新密钥 |
| 已过期 | 填入新密钥后再删除 |

同一个 OpenSea 账户的密钥共用请求上限。在同一个账户下创建多个密钥，上限也不会增加。

## OpenSea 提前启动

开启 **设置 → 发射引擎 → OpenSea 提前启动** 后，会从开始前 1 秒（T-1 秒）起请求铸造数据。它不会提前发送交易。在大型任务分组中，上限消耗得很快，请先看剩余额度再开启。

## 保护好密钥

- 不要把密钥发到 Discord、截图、日志或咨询里。
- 密钥一旦泄露，请到 OpenSea 吊销，并在应用里也删除。
- 咨询时，请发送被遮挡的密钥行、状态、应用版本和失败的时间。
