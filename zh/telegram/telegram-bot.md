# Telegram 机器人使用指南

Nogada Telegram 机器人是独立运行在服务器上的 24 小时铸造产品，不需要连接桌面应用。它只使用在机器人中登记的钱包、任务、RPC、代理和 OpenSea 密钥，无法查看或控制应用数据。

> 应用与机器人只共享产品规则和经过验证的铸造代码，不共享运行状态或数据。您可以在两者中登记同一个钱包地址；如果两者同时用该钱包发送交易，nonce 可能冲突。Nogada 会提醒，但不会阻止您的选择。

## 1. 无需应用即可登录

1. 在 Telegram 中打开 **@NOGADA\_Mint\_Bot**。
2. 发送 `/redeem 购买邮箱`。
3. 在 10 分钟内，将邮箱收到的 8 位验证码按 `/redeem 12345678` 发送。

无需安装应用，也不需要应用配对码。若从新的 Telegram 账号登录，旧聊天会退出，但机器人钱包和任务会保留。

## 2. 机器人钱包与机器人专用设置

在 **💼 钱包**中创建机器人钱包或导入私钥，并只存入铸造所需的小额资金。为实现 24 小时签名，机器人钱包密钥会加密保存在服务器上。大额资产请存放在独立的自托管安全钱包，并通过 **💸 提取**或 `sweep=` 转移资金和已确认的 NFT。

**🛠 设置**中的 RPC、代理和 OpenSea API 密钥仅属于机器人。应用中登记的值不会复制或同步过来。

## 3. 最简单的方式：智能铸造

1. 点击 **🔮 智能铸造**或发送 `/mint`。
2. 若只有一个机器人钱包，会自动选择；若有多个，请选择要执行的钱包。
3. 只需发送一个受支持的铸造链接或合约地址。例如：

   ```text
   https://opensea.io/collection/example
   ```

4. 请通过界面按钮手动选择合约实际部署的链。机器人不会仅凭输入自动确定最终链。
5. 若项目登记了多个阶段，机器人会显示其准确名称，请选择目标阶段。
6. 在铸造设置界面通过按钮确认或修改数量、发射方式、预约与 Gas，再创建任务。未来阶段会预填项目已公布的开始和结束时间。
7. 进入 **⚙️ 任务 → 🤖 机器人任务**再次确认内容，并提前点击 **Start** 进行准备。

智能铸造支持合约、区块浏览器链接、OpenSea collection/item/assets 链接、市场、Launchpad 和项目铸造站点。若受保护或缺少数据的页面无法解析，请改用合约或高级 ABI/Hex 任务。

* 默认数量为**每个已选钱包 1 个**。总目标显示为“钱包数 × 每钱包数量”。
* 每次铸造设置都可直接用按钮调整数量、发射方式、预约与 Gas，无需记忆命令参数。
* 若存在已知的单笔上限，机器人会按多个 nonce 拆分并执行准确数量，绝不会暗中减少。
* 缺失阶段编号或时间不完整时，不会猜成 Public 或“已结束”。
* 机器人不会猜测资格来阻止钱包选择或 Start。若实际签名、proof 等执行数据无法取得，会如实报告该钱包的准备/执行结果。

## 4. Start 与发射速度

所有机器人铸造都从**机器人任务中的 Start**开始。智能铸造查询完成不会自动广播。

* 立即 Start 会先被可靠保存，钱包、RPC、Gas、nonce 与铸造数据就绪后立即发射。
* 预约任务请提前点击 Start 进行准备。静态输入会预先准备，并在指定时刻广播第一笔交易。
* 同一 raw 交易可经多个 RPC 传播，但不会自动 RBF 或自动提高 Gas。
* 同一钱包可同时在应用中运行。机器人只提示 nonce 冲突风险，不会阻止。

## 5. 铸造设置与手动输入

普通智能铸造不需要命令参数。选择链与阶段后，可在铸造设置界面通过按钮设置：

* 数量：每钱包 1、2、3、5 个或自定义数量
* 发射：连射、单次或安全
* 预约：UTC 开始与可选结束时间，或项目公布的阶段时间
* Gas：自动，或自定义最大费用、tip 与 gas limit

旧的一行命令仍作为熟练用户选项保留。例如：

```text
/mint https://opensea.io/collection/example sepolia 1 at=1787802000 until=1787802300 fire=spam gas=400000 max=3 delay=250 tip=2 fee=7
```

普通智能铸造无需手写此格式。

自动查询不足或需要指定 calldata 时，使用 **⚙️ 任务 → 🤖 机器人任务 → ➕**。

```text
0x合约 [链] [每钱包数量] [每次发送的原生代币金额] [模式] + 选项
```

常用选项：

| 选项 | 含义 |
|---|---|
| `sig=mintPublic(uint256,address)` | 明确指定函数签名 |
| `args=2;{address}` | 函数参数；`{address}`替换为各机器人钱包 |
| `0x...` 模式 | 原样发送用户提供的 calldata |
| `fire=spam` | 直到 Stop 或准确铸造收据确认前重试 |
| `fire=safe` | 用户选择的含模拟单次路径 |
| `tip=5 fee=80 gas=120000` | 用户 Gas 设置（gwei / Gas 上限） |
| `max=200 delay=500` | 连发最大次数与间隔（毫秒） |
| `at=+5m` / `at=16:59` | UTC 预约开始 |
| `until=17:00` | UTC 连发停止时间 |
| `nft=0x...` | 通过路由器铸造时，收据中预期的 NFT 合约 |
| `sweep=0x...` | 将已确认 NFT 转到安全钱包 |

NFT 始终由签署铸造交易的机器人钱包接收，不支持独立铸造接收地址；如需在确认后转移，请使用 `sweep=`。

ABI/Hex 任务中的“数量”是收据中预期的 NFT 数量，不会改写 calldata。`nft=` 也仅用于路由器铸造时核验收据，不会更改调用目标或 calldata。只有 SeaDrop 等协议语义明确且可证明冲突时才会在发送前拒绝；机器人不会猜测任意 calldata 的含义来阻止发射。

## 6. 如何理解结果

普通流程只显示三类简短卡片：

* **阶段卡片：**项目、链、已确认时的当前状态，以及各准确阶段的价格、每钱包上限和公布时间
* **任务卡片：**任务编号、阶段、已选钱包与数量、发射方式和预约。同钱包 nonce 提醒只在此显示一次，不会在 Start、预约通知和结果中重复。
* **最终结果卡片：**已确认铸造、失败、确认中或未验证数量，简短的钱包/交易信息、浏览器链接，以及钱包/提取按钮

普通卡片不会显示内部平台名、minter 地址、selector 或准备诊断；若存在需要用户处理的实际错误，机器人仍会明确显示。

| 状态 | 含义 |
|---|---|
| 已提交/待确认 | 已有交易 hash，但收据尚未最终确认 |
| 铸造完成 | 成功收据中确认了准确的 NFT Transfer 合约、签名钱包和数量 |
| 失败 | 已确认链上 revert 或发射失败 |
| 铸造未验证 | 收据 status 成功，但无法证明预期 NFT 合约、签名钱包或数量 |

交易待确认时，机器人不会创建新 nonce，而会继续核对同一笔交易。未验证的铸造也不会自动重跑。您可以在任务详情中明确再次点击 Start，但机器人会先提示这将发送新交易并可能重复铸造。

## 7. 请牢记

* 应用与机器人的钱包、任务和设置彼此不可见，也不会同步。
* Start 前请确认所选钱包、每钱包数量、总数量、总金额、链和阶段。
* 更高的 tip 可能提高优先级，但不保证打包顺序。
* Drop Watch 的供应量变化并不能证明铸造已经开放；它只是信号，阶段与交易事实应以官方/链上数据为准。
* 不要在转发聊天、录屏或直播中暴露私钥、邮箱验证码或导出的密钥。
